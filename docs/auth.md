# 로그인, 사용자 권한, 검사 규칙

Croak의 로그인, 사용자 등급, 게이트 검사, 관리 화면을 설명한다. 2026-11-06 기준으로 게이트 서버에 배포된 상태를 적는다.

## 목표

- 사용자는 opencode에서 로그인한다. 키 값을 직접 다루지 않는다.
- 사용자마다 쓸 수 있는 에이전트와 도구가 다르다.
- 관리자는 모든 사용자의 프롬프트 기록과 통계를 본다.
- 보안 규칙을 어긴 요청을 탐지하고 관리자에게 보여 준다.

## 역할

역할은 두 축으로 나눈다. 사용 등급은 계정마다 하나를 둔다. 관리 권한은 필요한 계정에만 더한다. 한 계정이 여러 관리 권한을 함께 가질 수 있다.

### 사용 등급

| 등급 | 에이전트 | 도구 | 비밀정보 |
|---|---|---|---|
| `full` | 모든 에이전트 | 모든 도구 | 새 메시지에 있으면 거부한다. 느슨한 정책 프로필을 쓸 수 있다 |
| `standard` | `dev-main`, `dev-plan`, `dev-doc`, `dev-safe`, `pr-review`, 하위 에이전트(`general`, `explore`) | `bash`는 opencode 승인을 거친다 | 새 메시지에 있으면 거부한다 |
| `restricted` | `dev-safe`, `dev-doc`, `pr-review` | `bash`, `webfetch`, `websearch` 금지 | 대화와 첨부 어디에든 있으면 거부한다 |

세 등급 모두 opencode 내부 에이전트(`title`, `summary`, `compaction`)를 쓸 수 있다. 등급이 없는 키는 `restricted`로 본다.

`restricted` 사용자는 `dev-safe` 에이전트를 쓴다. `dev-safe`는 `bash`, 웹 도구, 하위 에이전트를 끄고 파일 수정은 승인을 받는다. 정의는 `codefrog/opencode` 저장소의 `opencode/agents/dev-safe.md`에 있다.

개인정보는 모든 등급에서 가린 뒤 보낸다. 첨부(이미지, PDF)의 개인정보는 관리 화면의 정책 메뉴에서 등급마다 거부로 바꿀 수 있다.

### 관리 권한

| 권한 | 할 수 있는 일 |
|---|---|
| `admin` | 계정 생성과 잠금, 등급 지정, 토큰 폐기, 정책 변경, 프롬프트 기록 열람, 통계와 위반 열람 |
| `auditor` | 프롬프트 기록 열람, 통계와 위반 열람. 계정과 정책은 바꾸지 못한다 |

관리자도 프롬프트 기록을 볼 수 있다. 대신 기록을 열어 본 일은 모두 관리 감사 기록에 남는다. 누가 언제 어느 사용자의 어느 날 기록을 열었는지 남긴다. 관리 감사 기록은 화면에서 지울 수 없다.

### 볼 수 있는 기록의 범위

- 보관 기록은 가린 뒤의 프롬프트와 답변이다. 원문은 어디에도 저장하지 않는다.
- 이미지와 PDF는 원본을 저장하지 않는다. 해시와, OCR로 읽고 가린 글자만 남긴다.
- 정책 프로필이 `store_prompt: none`이면 그 요청의 본문은 보관하지 않는다. 감사 기록과 사용량 기록만 남는다.
- 보관 기간은 90일이다.

## 구성

```
opencode ──HTTPS──▶ gate:8443 Caddy ─┬─▶ /v1/*, /health/liveliness   gate (LiteLLM + 가드레일) ──▶ ocr
                                    └─▶ /, /auth/*, /admin/*        auth (로그인, 관리 화면)
```

| 구성 요소 | 내용 |
|---|---|
| `proxy` | Caddy. 내부 인증 기관이 발급한 인증서를 쓴다. LiteLLM 관리 경로는 밖에서 닿지 않는다 |
| `gate` | LiteLLM과 가드레일(`croak_guardrail.py`). 4100 포트는 서버 안에서만 열린다 |
| `ocr` | 이미지와 PDF의 글자를 읽는다. Tesseract 한국어와 영어. 밖에서 닿지 않는다 |
| `auth` | FastAPI. 로그인 페이지, 확인 코드 발급, 토큰, 관리 화면 |
| `db` | Postgres. 게이트 DB `croak_gate`와 로그인 DB `croak_auth` |

모두 게이트 서버의 `~/croak` Compose에 들어간다. 기존 게이트(:4000)는 건드리지 않는다.

## 내부 인증서

1. `gateway/tls/make-certs.sh`가 내부 인증 기관(루트 CA)을 만든다. 유효 기간은 10년이다.
2. 루트 CA로 게이트 서버의 서버 인증서를 발급한다. 이름은 `gate.example.internal`과 `gate`이다. 유효 기간은 397일이다.
3. 루트 CA의 개인 키는 서버에 두지 않는다. 관리자 PC의 `~/.config/croak/ca`에 600 권한으로 둔다.
4. 루트 CA 인증서를 두 곳에 등록한다.
   - Windows 현재 사용자의 신뢰할 수 있는 루트 인증 기관: 브라우저의 로그인 페이지와 관리 화면용
   - WSL: `~/.bashrc`의 `NODE_EXTRA_CA_CERTS`. opencode(Bun)가 이 변수를 따른다

로그인 플러그인은 이 변수가 없어도 인증서 파일을 직접 읽어 로그인 서버에 접속한다.

## 로그인 흐름

`/connect`의 공급자 목록을 거치지 않는다. Croak 플러그인이 `/login` 명령을 직접 제공한다. 브라우저에서 로그인한 뒤 확인 코드를 붙여 넣는 방식이다.

1. 사용자가 opencode에서 `/login`을 실행한다.
2. 플러그인이 일회용 검증값(PKCE)을 만들고 Windows 기본 브라우저로 로그인 페이지를 연다.
3. 사용자가 로그인 페이지에서 아이디와 비밀번호를 입력한다.
4. 로그인에 성공하면 브라우저에 확인 코드와 "코드 복사" 버튼이 나온다.
5. 사용자가 확인 코드를 opencode 입력창에 붙여 넣는다.
6. 플러그인이 확인 코드와 검증값을 `POST /auth/token`으로 보내고 토큰을 받는다.
7. 플러그인은 요청마다 `Authorization` 머리글에 접근 토큰을 붙인다. 만료 10분 전에 갱신 토큰으로 새 접근 토큰을 받는다.

확인 코드는 5분 뒤 만료되고 한 번만 쓴다. 코드를 가로채도 검증값이 없으면 토큰으로 바꿀 수 없다.

로그인한 계정과 등급은 opencode 사이드바 맨 위와 첫 화면 입력창 오른쪽에 보인다. opencode 설정의 `apiKey`는 `login-required`라는 가짜 값이다. 로그인하지 않으면 요청이 통과하지 않는다.

### 로그인 유지 기간

평일에 일하는 방식에 맞춘다. 월요일에 한 번 로그인하면 그 주 내내 쓴다.

| 항목 | 기준 |
|---|---|
| 로그인 세션 | 로그인한 뒤 처음 오는 일요일 0시(한국 시간)에 끝난다. 일요일에 로그인하면 다음 일요일 0시에 끝난다 |
| 접근 토큰 | 24시간. 세션이 끝나는 시각을 넘지 않는다 |
| 갱신 토큰 | 세션이 끝나는 시각까지. 갱신할 때마다 바뀐다 |

세션이 끝나면 다음 요청이 거부되고, TUI에 `/login`으로 다시 로그인하라는 안내가 나온다.

### 토큰

| 토큰 | 정체 | 저장 위치 |
|---|---|---|
| 접근 토큰 | 게이트의 LiteLLM 가상 키. 메타데이터에 `croak_user`, `croak_tier`, `croak_roles`, `croak_session`이 들어 있다 | `~/.config/croak/session.json`, 600 |
| 갱신 토큰 | 로그인 서비스가 발급하는 임의 문자열. 서버에는 해시만 둔다 | 같은 파일 |
| 확인 코드 | 로그인 직후 한 번 쓰는 코드. 서버에는 해시만 둔다 | 서버 DB |

접근 토큰을 LiteLLM 가상 키로 만든 이유가 있다. 게이트가 이미 키를 검사하므로 별도 토큰 검증을 만들지 않는다. 관리자가 토큰을 폐기하면 로그인 서비스가 LiteLLM 키를 지운다. 그 뒤 첫 요청부터 거부된다.

등급은 키 메타데이터에서 읽는다. 키 메타데이터는 마스터 키로만 바꿀 수 있다. 사용자는 자기 등급을 올리지 못한다.

### 로그아웃

| 방법 | 동작 |
|---|---|
| `/logout` | 서버에서 갱신 토큰과 접근 토큰을 폐기하고, 로컬 파일을 지운다 |
| 일요일 0시 | 세션이 끝난다. 서버가 남은 접근 토큰을 지운다 |
| 관리자 폐기 | 관리 화면에서 사용자의 모든 세션을 끝낸다 |
| 계정 잠금, 등급과 관리 권한과 비밀번호 변경 | 그 계정의 모든 세션을 끝낸다. 다시 로그인하면 바뀐 권한이 적용된다 |

## 게이트 검사

가드레일은 요청마다 아래 순서로 검사한다. 거부하면 위반 기록을 남긴다.

| 순서 | 검사 | 걸리면 |
|---|---|---|
| 1 | 키 메타데이터에서 사용자와 등급을 읽는다. 등급이 없으면 `restricted` | - |
| 2 | 머리글 `x-croak-agent`의 에이전트가 등급의 허용 목록에 있는지 본다 | 403 `agent_denied`. 쓸 수 있는 에이전트를 함께 알려 준다 |
| 3 | 요청의 `tools` 목록에 등급이 금지한 도구가 있는지 본다 | 403 `tool_denied` |
| 4 | 머리글 `x-croak-session`의 세션을 처음 쓴 계정인지 본다 | 403 `foreign_session` |
| 5 | 키, 인증서, 비밀 파일에서 읽은 도구 결과를 뺀다 | 아래 "금지 경로". 거부하지 않고 빼고 보낸다 |
| 6 | 첨부(이미지, PDF)를 OCR로 읽어 비밀정보와 개인정보를 찾는다 | 아래 "첨부 검사" |
| 7 | 텍스트의 비밀정보를 찾는다. 새 사용자 메시지에 있으면 거부하고, 이전 대화와 도구 결과에 있으면 가린다. `restricted`는 어디에 있든 거부한다 | 400 `secret` |
| 8 | 텍스트의 개인정보를 가린다. 개인정보를 받지 않는 프로필이면 거부한다 | 400 `pii` |

에이전트 이름은 opencode가 보내므로 사용자가 바꿀 수 있다. 실제로 막는 장치는 3번이다. 모델은 요청에 실린 도구만 호출한다. opencode는 거부(deny)한 도구를 요청에서 빼기 때문에, `dev-safe`의 요청은 3번을 통과한다.

4번은 한 opencode 세션에서 다른 계정으로 로그인해 이전 대화를 이어 쓰는 일을 막는다. 화면에 이전 대화가 보이는 것까지 막지는 못한다. 대화는 PC의 opencode DB에 있기 때문이다. 세션 주인은 `data/sessions/`에 해시 이름으로 남는다.

### 탐지 규칙

규칙은 `gateway/croak_core.py`에 있다. 게이트와 OCR 서비스가 같은 파일을 쓴다.

| 종류 | 규칙 |
|---|---|
| 비밀정보 | 개인 키, AWS 키, GitHub 토큰, Slack 토큰, `sk-` 키, JWT, Bearer 토큰, `password=값` 형태, 문장형 비밀번호("pass1234로 패스워드를 설정"), 이름표 뒤의 짧은 비밀번호(`pw:1234`, `PIN: 4821`) |
| 개인정보 | 주민등록번호, 휴대폰과 일반 전화번호, 이메일, 카드번호(Luhn 검사), 여권번호, 이름표 뒤의 이름(`성명:`, `Name:`), 주소(이름표 뒤의 값, 도로명 주소, 괄호 안이나 시·군·구 뒤의 지번 주소, 앞에 붙은 우편번호) |

`true`, `none`, `string` 같은 설정값과 타입 이름, `${VAR}`나 `****` 같은 자리표시는 비밀번호로 보지 않는다. 이름표 없이 쓴 사람 이름은 잡지 못한다.

정책의 `allow`에 적은 값(커밋 작성자 이메일)은 시스템 프롬프트에서만 그대로 둔다. 사용자 메시지, 도구 결과, 첨부, 보관하는 답변에서는 가린다.

### 금지 경로

키, 인증서, 비밀 파일은 모델에 보내지 않는다. 목록은 `policy.yaml`의 `deny_paths`에 있다.

| 종류 | 대상 |
|---|---|
| 폴더 | `.ssh`, `.aws`, `.gnupg`, `.config/croak` (경로 어디에 있든 폴더 이름이 같으면) |
| 파일 | `.env`, `*.env`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*` |

`.env.example`, `docs/ssh.md`처럼 이름만 비슷한 파일은 막지 않는다.

두 겹으로 막는다.

| 위치 | 동작 |
|---|---|
| opencode 플러그인 `secret-paths.mjs` | 읽기, 쓰기, 목록, 검색 대상과 `bash` 명령에 이 경로가 있으면 실행 전에 막는다. `grep` 결과에 섞인 이 파일들의 줄을 뺀다 |
| 게이트 | 모델이 이 경로를 대상으로 부른 도구의 결과를 "보내지 않았다"로 바꾼다. 다른 도구 결과에 섞인 줄을 뺀다. opencode가 첨부로 넣은 파일도 같다 |

게이트에서 걸리면 위반 `path_blocked`로 남고 "설정 확인 필요" 경보가 뜬다. 정상이라면 opencode 플러그인이 먼저 막는다. 게이트에서 걸렸다면 그 PC에 플러그인이 설치되지 않았다는 뜻이다. 플러그인이 꺼진 경우도 같다.

`bash` 명령은 경로처럼 보이는 단어로만 판단한다. 변수나 스크립트를 거쳐 읽으면 놓칠 수 있다. `restricted`는 `bash`가 꺼져 있다.

### 첨부 검사

opencode는 이미지와 PDF를 `Read` 도구의 결과로 사용자 메시지에 넣는다. 이미지는 `image_url`, PDF는 `file` 형식의 base64 데이터다.

| 첨부 | 처리 |
|---|---|
| 이미지 | 원본 크기와 2배 확대로 두 번 읽는다. 한글 사이 띄어쓰기를 지운 뒤 규칙을 적용한다. 걸린 글자 위에 검은 상자를 칠해서 보낸다. 비밀정보는 그 줄 끝까지 가린다 |
| PDF | 텍스트 층을 읽는다. 텍스트가 없으면 쪽을 그려서 OCR로 읽는다. 걸린 것이 있으면 가린 텍스트로 바꿔 보낸다 |
| 읽을 수 없는 파일 | 보내지 않고 "읽지 못해 보내지 않았다"로 바꾼다 |

첨부의 비밀정보는 거부하지 않고 가린다. 첨부는 도구 결과이고, 거부하면 그 첨부가 대화에 남아 세션 전체가 막히기 때문이다. `restricted`만 거부한다.

첨부의 개인정보는 관리 화면에서 등급마다 가리기와 거부 중에 고른다. 거부로 정해도 이번 요청에 새로 들어온 첨부만 거부한다. 대화에 이미 있던 첨부는 가린다.

같은 이미지는 해시로 캐시한다. 이미지 한 장은 약 0.3초, 명함 사진은 약 2.7초가 걸렸다. OCR이라 손글씨, 흐린 사진, 작은 글자는 놓칠 수 있다.

### 정책 파일

```yaml
tiers:
  full:
    agents: ["*"]
    profiles: ["*"]
  standard:
    agents: [dev-main, dev-plan, dev-doc, dev-safe, pr-review, general, explore, title, summary, compaction]
  restricted:
    agents: [dev-safe, dev-doc, pr-review, title, summary, compaction]
    deny_tools: [bash, webfetch, websearch]
    secrets_scope: all
```

관리 화면에서 바꾼 첨부 처리 방식은 `settings/policy-overrides.json`에 따로 남는다. 나머지 규칙은 Git의 `policy.yaml`에서 바꾸고 배포한다.

## opencode 명령

| 명령 | 동작 |
|---|---|
| `/login` | 브라우저 로그인 뒤 확인 코드를 붙여 넣는다 |
| `/whoami` | 사용자 이름, 등급, 관리 권한, 허용 에이전트, 금지 도구, 로그인 유지 시각을 보여 준다 |
| `/agent-perm` | 등급 안에서 이 세션의 도구를 더 줄인다. 등급보다 넓힐 수는 없다 |
| `/logout` | 갱신 토큰을 폐기하고 로컬 토큰을 지운다 |

`/agent-perm`은 `tool-policy.mjs`의 세션 규칙을 쓴다. 사용자 편의 기능이고, 등급의 상한은 게이트가 지킨다.

## 관리 화면

`https://gate.example.internal:8443/admin`에 둔다. `/`로 들어와도 여기로 간다. `admin`과 `auditor`만 들어간다.

| 화면 | 내용 | 권한 |
|---|---|---|
| 대시보드 | 최근 7일 경보, 오늘의 요청, 거부, 위반, 토큰. 숫자와 경보를 누르면 해당 목록으로 간다 | `admin`, `auditor` |
| 프롬프트 기록 | 날짜, 사용자, 에이전트, 내용으로 찾는다. 가린 프롬프트와 답변, 이미지에서 읽은 글자를 본다 | `admin`, `auditor` |
| 통계 | 7일, 30일. 날짜별, 사용자별, 에이전트별, 모델별 요청, 거부, 위반, 토큰 | `admin`, `auditor` |
| 위반 | 경보와 위반 기록. 날짜, 거부만, 사용자로 거른다 | `admin`, `auditor` |
| 관리 감사 | 로그인, 계정 변경, 정책 변경, 기록 열람 내역 | `admin`, `auditor` |
| 정책 | 등급마다 첨부의 개인정보를 가리기와 거부 중에 고른다 | 바꾸기 `admin`, 보기 `auditor` |
| 사용자 | 계정 생성, 잠금, 등급과 관리 권한, 비밀번호 변경(확인칸과 보기 버튼), 세션 끝내기 | `admin` |

관리 화면은 아래 기록을 읽는다.

| 기록 | 위치 | 내용 |
|---|---|---|
| 감사 기록 | `data/audit/` | 요청마다 사용자, 등급, 에이전트, 처리 결과, 위반 코드, 첨부 수. 본문은 없다 |
| 사용량 기록 | `data/usage/` | 성공한 요청마다 토큰 수와 걸린 시간 |
| 프롬프트 기록 | `data/archive/` | 가린 프롬프트와 답변. 첨부는 해시와 가린 글자 |
| 관리 감사 | Postgres `events` | 로그인, 계정 변경, 정책 변경, 프롬프트 기록 열람 |

관리 화면 로그인은 opencode 로그인과 같은 계정을 쓴다. 관리 세션은 30분 동안 쓰지 않으면 끝나고, 길어도 8시간이다. 관리 화면은 요청마다 계정 상태와 관리 권한을 다시 확인한다. 잠긴 계정과 관리 권한을 뺀 계정은 다음 요청부터 들어오지 못한다.

## 위반 탐지

### 위반으로 기록하는 일

| 코드 | 화면 이름 | 내용 | 요청 처리 |
|---|---|---|---|
| `secret` | 비밀정보 거부 | 새 메시지에 비밀정보가 있다. `restricted`는 대화와 첨부 전체가 대상이다 | 거부 |
| `pii` | 개인정보 거부 | 개인정보를 받지 않는 프로필, 거부로 정한 등급의 새 첨부 | 거부 |
| `agent_denied` | 허용되지 않은 에이전트 | 등급에 없는 에이전트로 요청했다 | 거부 |
| `tool_denied` | 금지 도구 | 등급이 금지한 도구를 실었다 | 거부 |
| `foreign_session` | 다른 계정의 대화 | 다른 계정이 시작한 세션으로 요청했다 | 거부 |
| `downgraded` | 권한 없는 정책 요청 | 권한 없이 느슨한 프로필을 요청했다 | 기본 프로필로 처리 |
| `path_blocked` | 키, 인증서, 비밀 파일 접근 | 이번 요청에 새로 들어온 도구 결과가 금지 경로의 것이었다 | 빼고 처리 |
| `secret_in_history` | 도구 결과와 첨부의 비밀정보 | 이번 요청에 새로 들어온 도구 결과나 첨부에 비밀정보가 있어 가렸다. 이후 요청에서 다시 보내지는 같은 비밀정보는 세지 않는다 | 가린 뒤 처리 |
| `login_failed` | 로그인 실패 | 로그인에 실패했다 | 5회 실패하면 15분 잠금 |

### 경보 규칙

| 경보 | 기준 |
|---|---|
| 우회 시도 | `tool_denied`가 한 번이라도 있다. 정상 설정에서는 생기지 않는다 |
| 설정 확인 필요 | `agent_denied`나 `path_blocked`가 있다. 등급에 맞지 않는 opencode 설정, 꺼진 플러그인인 경우가 많다 |
| 다른 계정의 대화 | `foreign_session`이 있다 |
| 반복 위반 | 한 사용자가 1시간에 거부 3회 이상 |
| 비밀정보 유출 의심 | `secret_in_history`가 하루 5회 이상 |
| 로그인 공격 의심 | 한 계정에 하루 10회 이상 로그인 실패 |

경보는 관리 화면 맨 위에 표시한다.

## 보안 기준

- 비밀번호는 argon2id 해시로 저장한다. 최소 12자이고 아이디를 넣을 수 없다.
- 관리 화면 쿠키는 `HttpOnly`, `Secure`, `SameSite=Strict`다.
- 상태를 바꾸는 요청에는 CSRF 토큰을 검사한다. 관리자 로그인은 출처(Origin)도 검사한다.
- 스크립트는 요청마다 새로 만든 nonce가 붙은 것 하나만 허용한다. 확인 코드 복사와 비밀번호 보기 버튼에 쓴다.
- `Referrer-Policy`는 `same-origin`이다. `no-referrer`로 두면 브라우저가 폼 전송에 `Origin: null`을 보내 관리자 로그인이 막힌다.
- 확인 코드는 PKCE 검증값과 함께 써야 토큰으로 바뀐다.
- 갱신 토큰과 확인 코드는 해시로만 저장한다.
- 토큰과 비밀번호는 어떤 로그에도 남기지 않는다.
- LiteLLM 마스터 키는 서버의 `.env`(600)에만 둔다.
- 계정 생성과 비밀번호 입력은 사용자가 직접 한다.

## 운영 스크립트

모두 `gateway/`에 있다. 기록을 지우는 스크립트와 고치는 스크립트는 기본이 미리 보기다. `--apply`를 붙여야 실행한다.

| 스크립트 | 용도 |

| `auth/cli.py` | 서버에서 계정을 관리한다 |
