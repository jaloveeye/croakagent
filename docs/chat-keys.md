# 대화 전용 키

- **날짜**: 2026-11-12
- **사용자 결정**: Open WebUI 같은 대화 프로그램은 각자의 PC에서 쓰는 것을 전제로 한다. 그 프로그램에는 대화 전용 키를 쓴다.

## 1. 배경

croakcode 로그인 키는 24시간 유효하고 `~/.config/croak/session.json`에 있다. 이 키를 꺼내 Open WebUI에 넣을 수 있었다. 게이트의 마스킹과 기록은 그대로 적용됐다. 하지만 Open WebUI의 도구는 croakcode의 실행 허가 밖에서 돈다.

그래서 키를 둘로 나눴다. 로그인 키는 croakcode에서만 쓴다. 대화 프로그램에는 도구를 쓸 수 없는 키를 따로 준다.

## 2. 규칙

| 키 | 만드는 곳 | 게이트 검사 |
|---|---|---|
| 로그인 키 | croakcode `/login` | `x-croak-agent` 머리글이 없으면 거부한다(`client_required`) |
| 대화 전용 키 | croakcode `/chatkey` | 도구 선언, 도구 호출, 도구 결과가 있으면 거부한다(`chat_key_tools`) |
| 관리자가 만든 키 | `issue-key.sh` | 바뀌지 않았다 |

- 대화 전용 키의 에이전트는 항상 `chat`이다. 감사 기록과 사용량 기록에 `client: chat`이 남는다.
- 마스킹, 비밀정보 검사, 첨부 검사는 다른 키와 같다. 등급은 키를 만든 사용자의 등급이다.
- 대화 전용 키에는 croakcode 버전 머리글이 없다. 최소 버전 강제가 켜져 있어도 열린 대화 전용 키는 버전 검사를 통과한다. 지운 키와 만료된 키는 401(`chat_key_revoked`)을 받는다.
- 대화 전용 키로는 대화 전용 키를 만들 수 없다. 실행 허가와 모델 목록(`/v1/croak/*`)도 받을 수 없다.

## 3. 수명

| 항목 | 값 |
|---|---|
| 유효 기간 | 기본 30일, 최대 90일 |
| 사용자당 열린 키 | 5개 |
| 저장 | 키의 SHA-256만 `chat_keys` 표에 둔다. 키는 만들 때 한 번만 보여 준다 |

- 사용자가 `/chatkey`에서 지울 수 있다.
- 관리자는 관리 화면의 "대화 전용 키"에서 열린 키를 보고 폐기한다.
- 등급, 관리 권한, 비밀번호를 바꾸면 그 사용자의 키를 모두 폐기한다. 계정 잠금과 세션 끝내기도 같다.
- 주기 정리(`sweep`)가 만료된 키를 폐기하고 게이트 키를 지운다.

## 4. API

로그인 키(`Authorization: Bearer`)로 부른다.

| 요청 | 하는 일 |
|---|---|
| `GET /auth/chat-keys` | 열린 키 목록, 한도, 게이트 주소 |
| `POST /auth/chat-keys` `{"name", "days"}` | 새 키. 응답에만 키가 들어 있다 |
| `DELETE /auth/chat-keys/{id}` | 키를 지운다 |

## 5. 확인

- 단위 시험: `tests/test_core.py`의 `ChatKeys`, `auth/tests/test_auth_core.py`의 `ChatKeyRules`
- e2e(`tests/e2e.py` 15b와 관리 화면 절): 발급, 대화, 도구 거부, 로그인 키 거부, 한도, 삭제, 만료 정리, 관리자 폐기, 잠금 폐기를 확인했다.
- croakcode TUI에서 `/chatkey`로 키를 만들었다. 그 키로 대화는 200, 도구 선언은 403, 모델 목록은 200을 받았다. TUI에서 지우자 401을 받았다.
