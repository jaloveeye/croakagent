# 클라이언트 최소 버전

게이트는 배포 목록의 `minimum`을 최소 버전으로 쓴다. 요청의 `x-croak-client-version`이 없으면 HTTP 426을 돌려준다. 최소 버전보다 낮아도 426을 돌려준다. 응답은 `croakcode upgrade`를 안내한다.

Caddy는 공개 API 요청을 로그인 서비스에 먼저 확인한다. 로그인 서비스도 토큰 발급과 갱신, 계정 조회, 로그아웃을 검사한다. 실행 허가와 모델 목록 요청도 검사한다. 브라우저 로그인 화면과 상태 확인, 다운로드 경로에는 버전 머리글이 필요 없다.

배포 목록을 읽지 못하면 API 요청은 HTTP 503으로 중단한다. 목록의 내용이 잘못된 경우에도 중단한다. 목록의 최소 버전이 바뀌면 다음 요청부터 적용한다. 개발 버전은 같은 번호의 정식 버전보다 낮게 본다.

## 켜고 끄기

강제는 기본으로 꺼져 있다. 서버 `.env`의 두 값으로 정한다.

| 값 | 뜻 |
|---|---|
| `CROAK_CLIENT_VERSION_ENFORCE` | `1`이면 강제한다. 그 밖의 값이면 끈다. 꺼져 있으면 배포 목록 없이도 모든 요청이 통과한다 |
| `CROAK_CLIENT_MINIMUM` | 선택. 배포 목록의 `minimum` 대신 쓴다. 정식 버전(`X.Y.Z`)이어야 하고 `latest`보다 높으면 안 된다 |

`CROAK_CLIENT_MINIMUM`을 쓰면 같은 버전을 다시 올리지 않고 최소 버전을 올릴 수 있다. 값을 바꾼 뒤에는 로그인 서비스를 다시 띄운다.

## 적용 순서

1. 강제를 끈 채로 배포한다. 다운로드 경로가 열리고, 지금 클라이언트는 그대로 동작한다.
2. 배포 묶음을 올리고 모든 PC에 새 클라이언트를 설치한다. 새 클라이언트는 버전 머리글을 보낸다.
3. 서버 `.env`에 `CROAK_CLIENT_VERSION_ENFORCE=1`을 넣고 로그인 서비스를 다시 띄운다. 필요하면 `CROAK_CLIENT_MINIMUM`도 넣는다.

3번을 2번보다 먼저 하면 기존 클라이언트의 로그인과 API 요청이 차단된다. 강제를 켠 뒤 배포 목록이 없으면 API 요청은 HTTP 503으로 막힌다. 운영 배포와 `.env` 변경은 관리자가 한다.
